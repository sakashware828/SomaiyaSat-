How it works

Every ground pass is short, so the satellite must choose what to send. The queue is a hand-built binary min-heap, so the most important packet is always at the top. No heapq, no sorted() and no library queues are used. The code below is shown straight from the running page.

Scheduling rules
  • Priority order: TT&C (0) → SSTV images (1) → Codec2 / M17 voice (2).
  • Low battery (below 1.5 Wh): voice priority drops by 3. Poor link (below 0.4): SSTV priority drops by 2.
  • Power reserve: non-TT&C traffic may never push the battery below 0.75 Wh.
  • Fit check: if a packet does not fit in the remaining pass time it is skipped and a smaller one is tried.
  • Bounded buffer: 30 packets. When full, the lowest-priority packet is evicted.
  • Watchdog: if no TT&C was sent for 2 passes, a beacon is forced. SAFE mode: TT&C only.

1 · Min-heap: push and sift up

New packets are added at the end, then swapped upward until the heap order holds.


    
2 · Min-heap: remove and sift down
The hash map finds any packet in O(1), so it can be removed or re-keyed in O(log n).

    
3 · Re-prioritise (heapify)
When the battery or link changes, every key is recomputed and the heap rebuilt in O(n).

    
4 · Circular buffer log
Fixed memory: the newest entry overwrites the oldest, as onboard memory is limited.

    
5 · State machine table
A transition table defines which events are legal in each state. Anything else is ignored.

    
6 · Ground pass (greedy scheduler)
Pop the best packet, check time and power, transmit or defer, then put deferred packets back.
